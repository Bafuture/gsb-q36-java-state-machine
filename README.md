## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

业务对象的状态流转规则写得到处都是 if-else，改一条规则要翻好几个类，还经常漏掉某个分支。请从零实现一个通用状态机引擎，仓库目前只有一个空的 Maven 工程（只声明了 JUnit 5 与 AssertJ）。要求：1) 定义方式：支持用 Java DSL 定义状态、事件与迁移（from + event + to），并支持守卫条件（guard）与迁移动作（action）；2) 非法迁移：未定义的状态与事件组合必须被拒绝，错误信息要包含「当前状态 + 事件 + 当前允许的事件列表」，不得静默忽略；3) 异常语义：守卫抛异常视为不允许迁移；动作抛异常时状态不得发生变更，需保证并验证这一点；4) 超时迁移：支持为某个状态配置超时时间与超时后的目标状态，时间来源需抽象成可注入的接口以便测试；5) 状态持久化 SPI：定义状态存取接口并提供内存实现，说明如何接入数据库；6) 迁移记录：记录每次迁移的源状态、事件、目标状态、耗时与是否被拒绝，并提供查询接口；7) 导出：把状态机定义导出为 Mermaid 或 Graphviz 流程图文本；8) `mvn -q verify` 跑通，覆盖合法迁移、非法迁移、守卫失败、动作异常不改状态、超时迁移五类测试；9) README 说明设计取舍与已知限制。
